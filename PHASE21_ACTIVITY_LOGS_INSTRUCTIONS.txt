STATE CORPS CMS - PHASE 21 ACTIVITY LOGS

Purpose:
Add an admin-facing Activity Logs module using the existing audit_logs table.
This phase does not modify public pages, frontend design, existing content,
or delete/edit audit history.

INSTALLATION
1. Back up the project and database.
2. Extract this package into the existing publicV6 project root, merging files.
3. Import database/phase21_activity_logs.sql into statecorps_db.
4. Assign the new manage_activity_logs permission to the administrator account
   (and only editors who should be allowed to inspect the audit trail).
5. Visit /scadmin/activity-logs/index.php.

FEATURES
- Search description, user, entity, action, and IP.
- Filter by action, entity type, user, IP address, and date range.
- Paginated activity history.
- Detailed single-log view.
- Read-only: no delete, edit, truncate, or purge UI.
- Uses existing audit_logs records, including current login/logout/content logs.
- Adds indexes only when missing.

IMPORTANT
The module does not automatically retrofit missing AuditLogger calls into every
CMS manager. Existing areas that already call AuditLogger will appear in the
Activity Logs immediately. New managers should continue using the existing
AuditLogger::log(...) convention when an action must be recorded.

No public frontend changes are required.
